## 一、作品与开局

本作面向喜欢历史地图策略的玩家，也照顾第一次接触南明的玩家。玩家经营一方势力，在同一张全国地图上治理城池、用人、交涉和用兵，争取在剧本期限内统一天下。当时的人对政权、乡土、家族与生计各有考量，游戏用行动及其后果来呈现这些考量。

共同序幕是“北京失守的消息传到南京”。正式开局在甲申年五月（1644 年 6 月），即朱由崧在南京即位之后。单人模式下玩家从下表五家中选一家，其余各家由电脑行动。开局人物按历史预设，选中势力即可进入地图。

| 可选势力 | 开局代表人物 | 地图上首先要交代的处境 |
|---|---|---|
| 弘光朝廷 | 朱由崧 | 南京有朝廷，江北各镇另有统兵者。朝廷的号令需要将领落实。 |
| 清 | 顺治帝福临，摄政王多尔衮主政 | 入关后要在追击对手、接收城池和巩固新占区域之间分配兵力。 |
| 大顺 | 李自成 | 山海关失利后仍有军队和根据地，须决定在哪里站稳。 |
| 张献忠部 | 张献忠 | 入蜀途中，成都与大西政权是此后可能实现的目标。 |
| 福建郑氏 | 郑芝龙 | 奉明廷，掌握自己的船队与贸易关系。港口、海路和朝廷关系共同影响扩张。 |

地方军镇等其他实力派按实际影响进入地图。正式版城池以当时府、直隶州等治所及其辖区为主要参照。每座城池分别记录实际控制者、所奉政权和驻军。河港、关隘、渡口按交通作用设点。开局数据统一纪年、地名与时间截面。考据人员在势力图上附来源，对争夺中、归属待考等不确定处加以标注。

## 二、已定玩法

- **时间与目标。** 一月一回合，自甲申年五月开局，到壬寅年十二月（1662 年末）结算，约 220 个回合。统一天下可提前获胜；到期仍然分立，结局为“天下未定”。统一要满足两个条件：剧本覆盖的主要地区归于同一政权，独立争夺天下的对手均已退出。正式归附计入统一，盟约和停战则保留各自的控制权。玩家以郑氏主导、奉明完成统一也算获胜。制作全图时须列明计入胜利的地区，并在游戏中可查。
- **月度操作。** 先看上月变化，查看个别城市，然后任命人物、调拨钱粮、安排军事或交涉，提交本月命令。各方行动后生成下月局势。上月定下的方针持续执行。玩家可从月报里的事件跳到对应城市，查看变化原因。敌方内部情况只显示已知情报。
- **城池经营。** 治理涵盖政治、民生、经济、教育、防御和军事。人口影响赋税与兵源，战乱和征发影响民生，教育影响长期人才供给，粮饷约束驻军和远征。地方官执行方针，玩家掌握任免和资源取舍。
- **军事与外交。** 军队位置、围城状态、城池归属分开呈现。行军、围城、增援和交涉可以跨月，玩家可依新情报调整后续命令。野战失利可能使城市失去屏障，但只有陷城、献城、正式归附才会改变控制权。电脑势力也会结盟、分裂、议和和招降。
- **战斗。** 玩家一方参与的进攻、防守和围城都进入战斗画面。画面有部队动作，玩家在战斗中做选择（见第四节第 7 条）。
- **人物与继承。** 能力分统军、政务、谋略、外交、威望五项。人物的行动受关系、职权、驻地和当前状态约束。主将被俘时处理军权交接。君主被俘而势力尚存时，系统根据本局能联系上的宗室、将领和朝臣，列出监国、迎回或另立等可行方案，并说明各方案的支持者和代价。领袖更替后玩家可继续经营；势力实际分裂时，玩家可选择延续哪一支。
- **历史与平衡。** 历史提供起始条件和事件依据，后续走向由本局局势决定。关键史事和历史线索按第四节第 8 条出现，并会影响人物的决定。五家保留强弱、地理和权力结构上的差异，每家都要有可验证的统一路径。试玩重点记录弱势方能否通过经营、军事和外交取得主动。

## 三、已确认的制作方向

| 项目 | 制作要求 | 样稿要回答的问题 |
|---|---|---|
| 平台与操作 | 只做网页版，放在现有游戏合集的独立目录里，以桌面浏览器和鼠标为主。构建产物是静态页面，可本地启动，也可部署到 GitHub Pages。支持缩放、平移、点选、月末存档和继续游戏。规则核心与画面分离（见第五节），方便以后复用。 | 新玩家能否从开局直接找到所属城市、下达一道命令并看到结果？ |
| 美术 | 精致的 2D 页面游戏，不做 3D。界面是游戏式 HUD：深色漆木面板、铜金描边、资源与命令一律配图标、数值用大数字与数值条，避免成段文字。地图采用明末舆图的设色与山水笔意：地形、河流、纸色、印章、旗记、兵阵、界面框饰都由代码绘制。图标、纹理、音效、字体从允许再分发的免费资源中选用，来源和授权逐条登记。远看以河流、疆域、城名为主，放大后才出现城防、港口和驻军。实际控制者用势力色表示，所奉政权用旗记表示，旗形和文字辅助辨认。 | 缩小地图后还能否读出长江、找到南京，分清行军经过、围城和易主？ |
| 战斗画面 | 野战、攻城、守城各有画面，部队有冲锋、射击、接战、溃退等动作。玩家每个战斗回合下达指令，主将的计策可以改变局面。每场战斗都可以选择自动结算，自动结算与手动战斗使用同一套规则。 | 玩家能否看懂一场仗为什么胜或败，并感到自己的选择起了作用？ |
| 界面 | 地图占主画面；顶部是年月和推进按钮；选中城市后展开详情；月报按需展开。优先呈现钱粮、驻军和当前事务，城市的长期指标点开再看。 | 玩家能否从一条缺粮消息回到出问题的城，并知道是哪一项决定造成了变化？ |
| 文字与声音 | 月报用简明现代汉语，诏书和书信保留少量时代语汇。写战争和易主时讲清谁下令、谁承受后果。屠城、剃发令等事件以克制的文字直述史实与后果，不做血腥画面。普通月报和紧急军报用不同的简短音色区分，重要信息同时以文字呈现。 | 第一次接触南明的人能否说清发生了什么，以及这件事与自己有什么关系？ |
| 史事与线索 | 本局走向与历史相符时，关键史事按统一条件触发并影响人物决定；历史线索和背景事件按时间、地点出现在地图和月报上（见第四节第 8 条）。 | 玩家能否知道这件事在真实历史中如何发生，以及它在本局中改变了谁的态度？ |

第一份视觉样稿只做同一局势下的两个画面：全国势力总览，以及选中一座被围城市后的详情。主创用这两个画面确认画风、文字可读性和信息密度，之后再展开全图、战斗画面与人物资产。

## 四、核心系统

1. **地图结构。** 城池、关隘、渡口、港口是地图上的节点，节点之间由陆路、水路（江、河、运河）和海路相连。部队沿路线行军，补给沿路线运输。辖区色块只用来显示控制范围，不参与行军计算。每条路线记录通行所需天数和适用的兵种（如水师只走水路、海路）。
2. **历法与纪年。** 内部按顺序给月份编号。界面显示玩家所选势力所奉政权的年号和农历月，括号里注公元年：例如弘光方显示“崇祯十七年五月（1644）”，清方显示“顺治元年五月（1644）”。闰月单独算一个回合。史事和线索的日期统一按农历登记。
3. **月度结算。** 各方同时提交命令，再按固定阶段结算：交涉 → 行军 → 野战 → 围城与攻城 → 内政与钱粮 → 史事与线索 → 生成月报。结算到有玩家参与的战斗时暂停，进入战斗画面，打完后继续。同一阶段内的先后顺序由固定规则决定（如行军先比较路程，再比较统军能力），保证相同的局势和命令总得到相同的结果。
4. **政权、势力、人物。** 数据分三层。政权指朝廷与名号，如弘光、隆武、永历、清、大顺、大西。势力指实际掌兵掌地的集团，如弘光朝廷、江北各镇、郑氏、左良玉部。人物属于某个势力，可以改投。城池记录控制它的势力；势力记录所奉政权，并可改奉或自立。名号更替（弘光到隆武、永历）只改动政权一层，不必重建各个势力。
5. **下属军镇的服从。** 江北诸镇、左良玉部等奉朝廷但自有兵权的势力，在朝廷之下是半自主的下属。朝廷对它们下令后，执行结果取决于忠诚、利益、粮饷和将领关系，可能照办、拖延、打折扣或抗命。月报说明执行情况和原因。这是弘光开局的核心手感，十二回合试玩必须做出来。
6. **因果账。** 钱粮、人口、民心、兵员、城防的每一笔变动，都记下数值、所在城市、原因和源头（某道命令、某个事件或某场战斗，及其发生的月份）。月报、城市详情和“为什么”查询都从这本账生成。玩家点击一条变动，可以追溯到当初那项决定。
7. **战斗。**
   - **何时进入战斗。** 敌对部队在同一节点相遇时打野战，部队进攻有驻军的城池时打攻城战。玩家参与的战斗进入战斗画面；电脑之间的战斗，以及玩家选择自动的战斗，用同一套规则直接结算。
   - **野战。** 战场分左翼、中军、右翼三路，地形和天气影响战局。兵种分步、骑、火器、水师。每场战斗打 3 至 6 个回合。每回合玩家给每一路下令（进攻、坚守、迂回、齐射、突击、后撤）；主将可按谋略施放有次数限制的计策（伏兵、火攻、夜袭、阵前劝降等）。士气崩溃的一路会溃退。
   - **攻城与守城。** 城防有城墙耐久、城门和守军士气。攻方可选登城、炮击、掘地、围而不攻、劝降；守方可选固守、出城突击、夜袭、修城、求援。一场围城可以持续数月，每月打一场攻城战或只维持围困，粮尽、援军到达或城破时结束。援军到达后可以打解围战。
   - **战后结果。** 伤亡、士气、主将生死或被俘写入局势，并记入因果账。只有城破才改变城池控制权。
   - **范围安排。** 水战（长江渡江、海战）沿用同一框架，在完整剧本中补齐。
8. **史事与线索。**
   - **史事。** 关键历史事件，例如史可法督师江北、多尔衮致书史可法、高杰被杀、左良玉东下、扬州之战。每条史事登记日期范围、触发条件和影响。条件与本局局势相符时触发，同一事件全局只触发一次，所有势力看到的是同一事件。史事会改变相关人物的态度和倾向，如忠诚、降意、主战主和；也可能带来剧情选择。条件不符时，史事可以不发生，也可以按本局局势改写后发生（例如扬州已经失守，史可法就不会“死守扬州”）。
   - **线索。** 历史背景事件和人物动向，例如党争、三大案、剃发令、各地抗清、海上贸易，按时间、地点出现在地图和月报上。无论是否触发后续，线索都要提示给玩家，并对相关人物的态度产生小幅、持续的影响。
   - **史实对照。** 史事和线索都附一两句史实对照和资料来源，说明真实历史中如何发生、本局有何不同。
   - **首年候选。** 以下事件由考据核对日期后入库：史可法督师江北、江北四镇分防与高杰争扬州、马士英与阮大铖掌权、多尔衮致史可法书及复书、张献忠破成都并建大西、郑芝龙受封、李自成失潼关、高杰在睢州被许定国所杀、太子案与童妃案、左良玉“清君侧”东下、清军南下与扬州之战。
9. **电脑行为。** 电脑按规则行动，另外每家有一条随时间变化的战略倾向：例如清在开局几年倾向南下追击和接收，大顺倾向寻找根据地，郑氏重视港口与海路。倾向只决定大方向，具体用兵仍由局势决定。

## 五、技术方案

- **语言与构建。** 用 TypeScript 编写，Vite 构建。构建产物是纯静态文件，连同源码提交到仓库，GitHub Pages 和合集首页直接链接构建产物。本地用 `play.sh` 启动，默认端口 8110。
- **规则与画面分离。** `src/core` 存放全部规则，不访问页面、不读时间、不依赖浏览器。每月结算是一个纯函数：输入局势、各方命令和战斗选择，输出下月局势和月报。随机数由存档中的种子生成。战斗规则也放在核心里，战斗画面只负责播放结果和收集指令。
- **目录。** `src/core`（规则）、`src/data`（开局数据、人物、史事和线索，带类型检查的 TS 模块，每条可附来源和不确定标注）、`src/render`（地图与战斗绘制，Canvas 或 PixiJS）、`src/ui`（界面）、`assets`（素材与 `CREDITS.md`）、`tools`（数据校验与无浏览器测试）、`Docs`。
- **存档。** 存档是带版本号的 JSON。每月结算后自动存档，另有手动存档栏位。只在月与月之间存档，跨月的行军、围城、交涉都作为命令状态保存在局势里。读写经过一层存储接口，网页版使用浏览器本地存储，并提供导出和导入存档文件。
- **测试。** 规则核心可以不开浏览器直接运行，第六节的验收场景都写成自动测试，另有数据校验脚本检查节点、路线、人物和事件的引用是否完整。
- **素材与数据授权。** 只用允许再分发的素材：CC0 或公有领域优先，CC-BY 需要署名，全部登记在 `assets/CREDITS.md`。海岸线、河流底图可取自 Natural Earth（公有领域），再由代码绘成舆图风格。城池坐标与辖属由考据人员整理，学术地图集只作核对来源，不打包其图像或数据。界面字体选用开源中文字体（如思源宋体），子集化后随游戏发布。

## 六、开发顺序与验收

| 交付 | 范围 | 通过条件 |
|---|---|---|
| 地图与操作样稿 | 第三节所述的两个画面，可点选城市，查看从属、驻军和军情。使用真实节点数据和一个围城局面。 | 试玩者能指出谁控制该城、谁在城外、城是否已经易主。 |
| 十二回合试玩 | 玩家选弘光，从甲申年五月起玩满十二个月。全图显示五家，细做南京、江北、长江沿线和福建沿海的三四十个节点，其余地区为粗粒度大区，其他四家以简化规则行动。需要接通：一条城池经营因果链；江北诸镇的服从机制；野战与攻城两种战斗画面；一场可以增援的跨月围城；一种可以促成易主的交涉；首年史事与线索各若干条；存档与读档。 | 连续玩满十二个月；玩家能从月报解释一座城的钱粮变化。用预设局面分别验证：战败后仍能守城、献城后改属、结盟后双方仍保有控制权、读档后进行中的围城可以继续。另验：手动战斗与自动结算在相同选择下结果一致；史事在条件相符时只触发一次，条件不符时不触发或改写后触发；线索按时出现，并在人物态度上留下可查的影响。 |
| 完整剧本 | 五家均可选，补齐全国地区、历史人物、地方势力、教育与人才、继承与分裂、水战、全期史事与线索，以及统一结算。 | 五家分别完成从开局到统一的验证。另验到期分立、君主被俘后续局、奉明统一。通过试玩比较五家的难度和决策空间，再调整初始资源和电脑行为。 |

策划与历史研究先交开局地图、城市与人物清单，以及首年史事与线索清单（附日期、条件、来源）。开发依据同一份开局数据，先做地图样稿，再做月度试玩。
